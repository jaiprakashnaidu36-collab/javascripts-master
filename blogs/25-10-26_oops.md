# Object-Oriented Programming (OOP) in JavaScript

Object-Oriented Programming (OOP) is a programming paradigm based on the concept of **objects**, which contain data (properties) and code (methods).

JavaScript is a multi-paradigm language that supports OOP. However, unlike class-based languages (such as Java or C++), JavaScript was originally built on a **prototype-based model**. With ECMAScript 2015 (ES6), JavaScript introduced the `class` syntax, providing a cleaner, more familiar abstraction over prototypes.

## 1. Objects & Object Creation

An object in JavaScript is a collection of key-value pairs.

### Method 1: Object Literal
The simplest way to create an object.

```javascript
const car = {
  brand: "Toyota",
  model: "Corolla",
  start() {
    console.log(`${this.brand} ${this.model} is starting...`);
  }
};

car.start(); // Toyota Corolla is starting...
```

### Method 2: Constructor Function (Pre-ES6)
Before ES6 classes, constructor functions were the standard way to create reusable blueprints.

```javascript
function Car(brand, model) {
  this.brand = brand;
  this.model = model;
}

// Adding a method via prototype (memory efficient)
Car.prototype.start = function() {
  console.log(`${this.brand} ${this.model} is starting...`);
};

const car1 = new Car("Honda", "Civic");
car1.start(); // Honda Civic is starting...
```

## 2. Prototypes and Prototype Chaining

Every JavaScript object has a private property that holds a link to another object called its **prototype**. That prototype object has a prototype of its own, and so on until an object is reached with `null` as its prototype. This chain is known as the **prototype chain**.

```javascript
const animal = {
  eats: true,
  walk() {
    console.log("Animal walks");
  }
};

const dog = Object.create(animal);
dog.barks = true;

console.log(dog.barks); // true (own property)
console.log(dog.eats);  // true (inherited from animal prototype)
dog.walk();             // Animal walks (inherited)
```

## 3. ES6 Classes

ES6 introduced syntactical sugar over constructor functions and prototype inheritance.

```javascript
class Person {
  // Constructor: Initializes instances
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  // Instance method (lives on Person.prototype)
  greet() {
    console.log(`Hello, my name is ${this.name} and I am ${this.age} years old.`);
  }

  // Static method: Belongs to the class, not instances
  static species() {
    return "Homo sapiens";
  }
}

const alice = new Person("Alice", 28);
alice.greet(); // Hello, my name is Alice and I am 28 years old.
console.log(Person.species()); // Homo sapiens
```

## 4. The 4 Pillars of OOP

### 1. Encapsulation
Encapsulation means bundling data (attributes) and the methods that operate on that data inside a single unit (class), while restricting direct access to some components using visibility scopes (private fields).

In modern JS, private fields and methods are prefixed with `#`.

```javascript
class BankAccount {
  #balance = 0; // Private field

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  deposit(amount) {
    if (amount <= 0) throw new Error("Deposit amount must be positive");
    this.#balance += amount;
  }

  withdraw(amount) {
    if (amount > this.#balance) throw new Error("Insufficient funds");
    this.#balance -= amount;
  }

  // Getter for read-only access
  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount("John", 500);
account.deposit(200);
console.log(account.getBalance()); // 700

// Attempting to access private field directly:
// console.log(account.#balance); // SyntaxError: Private field '#balance' must be declared in an enclosing class
```

### 2. Abstraction
Abstraction means hiding complex implementation details and exposing only the essential features of an object. This reduces complexity and allows focusing on interactions rather than internal mechanics.

```javascript
class CoffeeMachine {
  #waterAmount = 0;

  // Public interface
  setWater(amount) {
    if (amount < 0) throw new Error("Negative water not allowed");
    this.#waterAmount = amount;
  }

  // High-level public command
  makeCoffee() {
    this.#boilWater();
    this.#brewGrinds();
    console.log("Coffee is ready!");
  }

  // Low-level internal operations hidden from the user
  #boilWater() {
    console.log("Boiling water...");
  }

  #brewGrinds() {
    console.log("Brewing coffee grounds...");
  }
}

const machine = new CoffeeMachine();
machine.setWater(200);
machine.makeCoffee();
// The caller doesn't need to know how boiling or brewing works internally.
```

### 3. Inheritance
Inheritance allows a child class to inherit properties and methods from a parent class using the `extends` keyword, promoting code reuse. The `super` keyword calls the parent constructor or method.

```javascript
class Vehicle {
  constructor(make, model) {
    this.make = make;
    this.model = model;
  }

  start() {
    console.log(`${this.make} ${this.model} engine started.`);
  }
}

class ElectricCar extends Vehicle {
  constructor(make, model, batteryCapacity) {
    super(make, model); // Call parent class constructor
    this.batteryCapacity = batteryCapacity;
  }

  charge() {
    console.log(`Charging ${this.make} ${this.model} (${this.batteryCapacity} kWh battery)...`);
  }
}

const tesla = new ElectricCar("Tesla", "Model 3", 75);
tesla.start();  // Inherited from Vehicle
tesla.charge(); // Defined in ElectricCar
```

### 4. Polymorphism
Polymorphism allows different classes to define the same interface or method name, each with its own implementation. In JavaScript, this is typically achieved via **method overriding**.

```javascript
class Shape {
  calculateArea() {
    return 0;
  }
}

class Circle extends Shape {
  constructor(radius) {
    super();
    this.radius = radius;
  }

  // Overriding calculateArea
  calculateArea() {
    return Math.PI * this.radius ** 2;
  }
}

class Rectangle extends Shape {
  constructor(width, height) {
    super();
    this.width = width;
    this.height = height;
  }

  // Overriding calculateArea
  calculateArea() {
    return this.width * this.height;
  }
}

// Polymorphic behavior: Calling the same method signature on different shapes
const shapes = [new Circle(5), new Rectangle(4, 6)];

shapes.forEach((shape) => {
  console.log(`Area: ${shape.calculateArea().toFixed(2)}`);
});
// Output:
// Area: 78.54
// Area: 24.00
```

## 5. Summary Cheatsheet

| Concept | JavaScript Mechanism | Example / Keyword |
| :--- | :--- | :--- |
| **Object** | Key-value mapping | `{ name: "Sam" }` |
| **Class** | Prototype blueprint syntax | `class MyClass { ... }` |
| **Encapsulation** | Hiding private state | `#privateField`, getters/setters |
| **Abstraction** | Exposing clean APIs; hiding internals | Public methods executing private steps |
| **Inheritance** | Deriving subclasses | `class Sub extends Super`, `super()` |
| **Polymorphism** | Overriding inherited behavior | Child class re-declares `methodName()` |
