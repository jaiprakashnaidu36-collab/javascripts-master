# JavaScript Async/Await: Complete Deep-Dive Guide

`async` and `await` are syntactic sugar built on top of JavaScript **Promises**. They enable you to write asynchronous code that reads sequentially, like synchronous code, while retaining non-blocking execution under the hood.

## 1. Under the Hood: How Async/Await Works

* Any function marked with `async` **always returns a Promise**.
  - If you return a primitive (e.g., `return 42;`), JavaScript wraps it in `Promise.resolve(42)`.
  - If you throw an error (e.g., `throw new Error('Boom');`), JavaScript wraps it in `Promise.reject(error)`.
* The `await` expression pauses the execution of the enclosing `async` function until the Promise settles (resolves or rejects).
* While paused, the main thread is **not blocked**; other tasks in the event loop continue to execute.

## 2. Basic Syntax & Function Declarations

You can use `async` with any function declaration style:

```javascript
// 1. Function Declaration
async function fetchData() {
  return "data";
}

// 2. Function Expression
const fetchDataExpr = async function() {
  return "data";
};

// 3. Arrow Function
const fetchDataArrow = async () => {
  return "data";
};

// 4. Object Method
const apiService = {
  async getUser(id) {
    return { id, name: "Alice" };
  }
};

// 5. Class Method
class UserService {
  async fetchUserProfile(id) {
    return { id, role: "admin" };
  }
}

// 6. Immediately Invoked Async Function Expression (IIAFE)
(async () => {
  const result = await fetchData();
  console.log(result);
})();
```

## 3. The `await` Keyword in Detail

* `await` can only be used inside an `async` function or at the top level of an ES module.
* `await` unwraps thenables: if an object has a `.then()` method, `await` treats it like a native Promise.
* Awaiting non-promise values works, but immediately resolves:

```javascript
async function demonstration() {
  // Awaiting a Promise
  const resolvedValue = await Promise.resolve("resolved!");
  console.log(resolvedValue); // "resolved!"

  // Awaiting a primitive (converts to Promise.resolve(100))
  const num = await 100;
  console.log(num); // 100
}
demonstration();
```

## 4. Error Handling: `try...catch...finally`

When an awaited Promise rejects, it throws an exception inside the `async` function.

### Basic Try / Catch / Finally

```javascript
async function loadUserData(userId) {
  let isCleaningUp = false;

  try {
    console.log("Fetching user...");
    const response = await fetch(`https://api.example.com/users/${userId}`);
    
    if (!response.ok) {
      throw new Error(`Server returned HTTP ${response.status}`);
    }

    const user = await response.json();
    return user;
  } catch (error) {
    // Intercepts network failure, JSON parsing error, or manually thrown Error
    console.error(`Failed to load user ${userId}:`, error.message);
    
    // Optional: Return a fallback value or re-throw
    return null;
  } finally {
    // Always runs, regardless of success or failure
    isCleaningUp = true;
    console.log("Cleanup executed. Finished operation.");
  }
}
```

### Catching Specific Errors

```javascript
class NetworkError extends Error {}
class ValidationError extends Error {}

async function processOrder(orderPayload) {
  try {
    await validatePayload(orderPayload);
    await submitOrder(orderPayload);
  } catch (err) {
    if (err instanceof ValidationError) {
      console.warn("User input issue:", err.message);
    } else if (err instanceof NetworkError) {
      console.error("Network outage during order submission:", err.message);
    } else {
      console.error("Unexpected fatal error:", err);
      throw err; // Re-throw unknown errors
    }
  }
}
```

### Alternative Go-Style Error Tuple Pattern

To avoid nesting deeply in multiple `try/catch` blocks, use a tuple wrapper:

```javascript
// Helper wrapper
const to = (promise) =>
  promise
    .then((data) => [null, data])
    .catch((err) => [err, null]);

// Usage
async function getUserAndPosts(userId) {
  const [userErr, user] = await to(fetchUser(userId));
  if (userErr) {
    console.error("Could not fetch user:", userErr);
    return;
  }

  const [postsErr, posts] = await to(fetchPosts(user.id));
  if (postsErr) {
    console.error("Could not fetch posts:", postsErr);
    return;
  }

  return { user, posts };
}
```

## 5. Sequential vs. Concurrent Execution

### Sequential (Waterfall) Execution

Each `await` blocks until the previous one finishes. **Use this only when task B strictly depends on task A.**

```javascript
// Total time: ~3 seconds (1s + 2s)
async function sequential() {
  const user = await fetchUser();       // Takes 1 second
  const orders = await fetchOrders();   // Takes 2 seconds
  return { user, orders };
}
```

### Concurrent Execution with `Promise.all`

If independent requests don't rely on one another, run them in parallel. **Fails fast** if any single Promise rejects.

```javascript
// Total time: ~2 seconds (max(1s, 2s))
async function concurrent() {
  const [user, orders] = await Promise.all([
    fetchUser(),   // 1s
    fetchOrders()  // 2s
  ]);
  return { user, orders };
}
```

### Resilient Concurrency with `Promise.allSettled`

Waits for all operations to finish, regardless of whether they fulfilled or rejected.

```javascript
async function loadDashboard() {
  const results = await Promise.allSettled([
    fetchUserProfile(),
    fetchNotifications(),
    fetchAnalytics()
  ]);

  const [profileRes, notifRes, analyticsRes] = results;

  const profile = profileRes.status === "fulfilled" ? profileRes.value : null;
  const notifs  = notifRes.status === "fulfilled"  ? notifRes.value  : [];
  const analytics = analyticsRes.status === "fulfilled" ? analyticsRes.value : null;

  return { profile, notifs, analytics };
}
```

### Race Conditions with `Promise.race` and `Promise.any`

* **`Promise.race([p1, p2])`**: Resolves or rejects as soon as **any** promise settles.
* **`Promise.any([p1, p2])`**: Resolves as soon as **any single** promise fulfills (ignores errors unless *all* fail, throwing an `AggregateError`).

```javascript
// Get response from quickest mirror
async function fetchFromFastestMirror(mirrors) {
  try {
    const fastestData = await Promise.any(mirrors.map(url => fetch(url).then(r => r.json())));
    return fastestData;
  } catch (aggregateError) {
    console.error("All mirrors failed:", aggregateError.errors);
  }
}
```

## 6. Loops & Asynchrony

### For...of vs. Array.prototype.forEach

> ⚠️ **NEVER use `async/await` inside `forEach` or `map` expecting sequential delays!**  
> `forEach` does not await promises; it fires all callbacks synchronously in the same tick.

```javascript
const userIds = [1, 2, 3];

// ❌ WRONG: Executes in parallel without waiting, and errors are unhandled
userIds.forEach(async (id) => {
  await deleteUser(id); 
});

//  CORRECT: Sequential execution (one after another)
async function deleteSequentially() {
  for (const id of userIds) {
    await deleteUser(id);
  }
}

//  CORRECT: Parallel execution across an array
async function deleteInParallel() {
  await Promise.all(userIds.map((id) => deleteUser(id)));
}
```

### Asynchronous Iterators (`for await...of`)

Iterates over async iterables, such as paginated streams or event sources:

```javascript
async function* paginatedFetcher(endpoint) {
  let page = 1;
  let hasMore = true;

  while (hasMore) {
    const res = await fetch(`${endpoint}?page=${page}`);
    const data = await res.json();
    yield data.items;
    hasMore = page < data.totalPages;
    page++;
  }
}

// Consumption
async function displayAllItems() {
  for await (const itemsChunk of paginatedFetcher('/api/items')) {
    console.log("Received chunk:", itemsChunk);
  }
}
```

## 7. Top-Level Await

In ES Modules (`.mjs` files or `<script type="module">`), you can use `await` outside of an `async` function:

```javascript
// dbConnection.js (ES Module)
export const connection = await initializeDatabaseConnection({
  host: process.env.DB_HOST,
  port: 5432
});

// Config loader
const configResponse = await fetch('/config.json');
export const appConfig = await configResponse.json();
```

## 8. Common Pitfalls & Anti-Patterns

### Pitfall 1: Unintentional Waterfalls
```javascript
// ❌ Bad: Slow waterfall
async function getProfileData() {
  const bio = await getBio();
  const avatar = await getAvatar();
  return { bio, avatar };
}

//  Good: Concurrent
async function getProfileData() {
  const [bio, avatar] = await Promise.all([getBio(), getAvatar()]);
  return { bio, avatar };
}
```

### Pitfall 2: Redundant `return await`
```javascript
// ❌ Redundant: Extra microtask tick without benefit
async function getData() {
  return await fetch('/data');
}

//  Clean: Directly return the promise
async function getData() {
  return fetch('/data');
}

// ⚠️ Exception: Keep `return await` ONLY inside a try/catch block
// so local catch can capture rejection!
async function safeGetData() {
  try {
    return await fetch('/data'); // Needed so catch block triggers on rejection
  } catch (err) {
    return null;
  }
}
```

### Pitfall 3: Forgetting `await`
```javascript
async function run() {
  const result = calculatePromise(); // Forgot `await`
  console.log(result); // Outputs: [object Promise], not the resolved value!
}
```

## 9. Real-World Production Recipes

### Retry Logic with Exponential Backoff

```javascript
async function retryWithBackoff(fn, retries = 3, delay = 500, backoff = 2) {
  try {
    return await fn();
  } catch (error) {
    if (retries <= 0) {
      throw error;
    }
    console.warn(`Retrying after failure... attempts left: ${retries}`);
    await new Promise((resolve) => setTimeout(resolve, delay));
    return retryWithBackoff(fn, retries - 1, delay * backoff, backoff);
  }
}

// Usage:
// const data = await retryWithBackoff(() => fetch('/unstable-endpoint').then(r => r.json()));
```

### Async Timeout Wrapper

```javascript
function withTimeout(promise, ms = 5000) {
  let timeoutId;

  const timeoutPromise = new Promise((_, reject) => {
    timeoutId = setTimeout(() => {
      reject(new Error(`Operation timed out after ${ms}ms`));
    }, ms);
  });

  return Promise.race([promise, timeoutPromise]).finally(() => {
    clearTimeout(timeoutId);
  });
}

// Usage:
// const user = await withTimeout(fetchUser(10), 3000);
```

### Batched Concurrency Pool (Throttling)

Execute hundreds of async jobs without overloading network sockets or database connection pools:

```javascript
async function pool(items, limit, asyncFn) {
  const executing = new Set();
  const results = [];

  for (const item of items) {
    const task = Promise.resolve().then(() => asyncFn(item));
    results.push(task);
    executing.add(task);

    const clean = () => executing.delete(task);
    task.then(clean).catch(clean);

    if (executing.size >= limit) {
      await Promise.race(executing);
    }
  }

  return Promise.all(results);
}

// Usage: Run 100 fetches with maximum 5 in parallel at any given time
// const urls = [...];
// const allResponses = await pool(urls, 5, (url) => fetch(url).then(r => r.json()));
```
